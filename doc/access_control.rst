**************
Access Control
**************

Seven user groups are provided. Access is additive — a user may belong to
multiple groups.

``group_real_estate_admin`` — **Real Estate Administration**
   Full CRUD on all module models. Intended for system administrators and
   property managers with unrestricted access. The built-in ``admin`` user
   is automatically assigned to this group at installation.

``group_real_estate_object`` — **Real Estate Object**
   Full CRUD on property and object data (``base_object``, ``address``,
   ``measurement``, ``meter_reading``, ``object_party``, ``occupancy``).
   Read-only access to contract, billing, and configuration models.
   Intended for facility managers who maintain the property master data
   but do not manage contracts or run settlements.

   *Exception:* also has full CRUD on ``real_estate.option_rate`` (in
   addition to ``group_real_estate_admin``), since option rates are
   maintained together with the property/object master data via the
   *Update Option Rates* wizard — see `Option Rate <option_rate.rst>`__. The
   ``group_real_estate_contract`` and ``group_real_estate_billing`` groups
   remain read-only on it.

``group_real_estate_contract`` — **Real Estate Contract**
   Full CRUD on contract data (``contract``, ``contract.term``,
   ``contract.item``, ``contract.log``, ``contract.term.cash_flow``,
   ``contract.term.tax``, ``account_contract``).
   Read-only access to property, billing, and configuration models.
   Intended for property managers / letting agents.

   *Exception:* also has full CRUD on
   ``real_estate.contract.term.adjustment`` (in addition to
   ``group_real_estate_admin``) — see the *Contract Term Adjustment*
   wizard in `Wizards <wizards.rst>`__. The
   ``group_real_estate_object`` and ``group_real_estate_billing`` groups
   remain read-only on it.

``group_real_estate_billing`` — **Real Estate Billing**
   Full CRUD on all operating cost and settlement models
   (``billing_unit``, ``billing_unit.log``, ``billing_unit.moves``,
   ``settlement_unit``, ``settlement_result``, ``cost_share``,
   ``cost_category_group``, ``cost_type``,
   ``account.configuration.real_estate``), and on the BVED external
   billing models (``bved.service_provider``, ``bved.provider_assignment``,
   ``bved.object_number``, ``bved.object_number.m_satz_line``,
   ``bved.export``, ``bved.import``, ``bved.import.line`` — see *BVED
   External Billing Interface* below).
   Read-only access to property and contract models.
   Intended for the operating cost accountant who runs the annual
   settlement but does not modify contracts or property master data.

   *Exception:* the ``group_real_estate_contract`` group also has read-only
   access to all six BVED models (shared master/exchange data, not
   contract-specific); ``group_real_estate_object`` has none.

``group_real_estate_view`` — **Real Estate View** (German: *Immobilien Anzeigen*)
   Read-only (``perm_read=True``, ``perm_write``/``perm_create``/
   ``perm_delete=False``) on every module model that has explicit
   ``ir.model.access`` records — i.e. every model listed in the
   permission matrix below, without exception. Defined in its own file,
   ``group_real_estate_view.xml`` (one ``res.group`` record plus one
   ``ir.model.access`` record per model, generated by enumerating every
   ``<record model="ir.model.access">`` across the module's XML files via
   an XML parser — not a plain-text/regex search, which would also match
   commented-out ``ir.model.access`` blocks such as the disabled
   ``real_estate.address.format`` one in ``address.xml``). Intended for
   users who need full visibility across the module (e.g. auditors,
   read-only reporting accounts) without being able to change anything,
   independent of which of the other four functional groups they would
   otherwise need for write access. Deliberately scoped to the module's
   own ``real_estate.*`` models only — it does not touch access to core
   models the module merely extends with extra fields (``party.party``,
   ``account.invoice``, ``account.move.line``, ``company.company``),
   since those already have their own, separate access control.

``group_account_view`` — **Accounting View** (German: *Rechnungswesen Anzeigen*)
   Read-only counterpart to core's own ``account.group_account``
   ("Accounting" / German *Rechnungswesen*) group — same ten models
   (``account.aged_balance``, ``account.general_ledger.account``,
   ``account.general_ledger.account.party``, ``account.invoice``,
   ``account.invoice.line``, ``account.invoice.payment.mean.rule``,
   ``account.journal.period``, ``account.move``,
   ``account.move.reconciliation``, ``account.move.template``) that
   ``group_account`` itself has explicit ``ir.model.access`` records for
   (found by querying a live database's ``ir.model.access`` table for
   that group — ``group_account``'s own permissions are additive with
   its child ``group_account_admin``'s via ``res.group.parent``, so
   ``account.account``/``account.period``/``account.fiscalyear``/
   ``account.tax`` etc. are only reachable through that child group, not
   directly on ``group_account``, and are intentionally excluded here).
   All ten downgraded to read-only. Defined in ``group_account_view.xml``
   — kept as a module of its own file, not merged into
   ``group_real_estate_view.xml``, since it grants access on core
   accounting models rather than this module's own; added here (rather
   than patched into core's ``account`` module, which this module must
   not modify) because ``real_estate`` already depends on ``account``.
   Independent of ``group_real_estate_view`` — a user typically needs
   both to see the full picture (real-estate objects/contracts plus the
   accounting moves/invoices behind them) without being able to change
   either.

   ``group_account_view.xml`` also links the group to the top-level
   *Rechnungswesen* menu (``account.menu_account``) via
   ``menu_account_group_account_view`` (``ir.ui.menu-res.group``), since
   that menu is only shown to explicitly linked groups.

``group_party_access`` — **Party Access** (German: *Partner Zugriff*)
   Party editing is a separately-assigned privilege: only members of
   ``group_party_access`` may create, modify, or delete parties; every
   *other* role — including this module's own
   ``group_real_estate_admin``/``object``/``contract``/``billing`` and
   both "view" groups above — has read-only access (so party names still
   display wherever a party is referenced: contracts, invoices, lists...). Defined in ``group_party_access.xml``:
   a ``_default`` (no-group) ``ir.model.access`` row
   (``perm_read=True``, the rest ``False``) plus one full-CRUD row for
   ``group_party_access`` itself. The built-in ``admin`` user is
   auto-assigned to this group at installation (``res.user-res.group``),
   matching how core's own ``group_account``/``group_account_admin`` and
   this module's own ``group_real_estate_admin`` already do, so the
   out-of-the-box admin account is not locked out.

   .. warning::
      Groups of optional modules (``sale``, ``purchase``, ...) are not
      included. Users of such modules who need to create or edit parties
      must be added to ``group_party_access`` by an administrator
      (Administration → User → the user's *Groups* field).
